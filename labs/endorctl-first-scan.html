Your First Endor Labs Scan

Guided
🕓 45 min 🏆 100 XP 🔄 SCA 📚 6 steps

🎯 Lab Objectives

  • Install endorctl and activate your Endor Labs API token
  • Connect a GitHub repository with the Endor Labs GitHub App
  • Run your first full scan with endorctl scan
  • Interpret findings, severities, and the dependency tree
  • Understand function-level reachability and read a call path
  • Fix your first reachable finding and verify it with a re-scan
1

Install endorctl and Activate Your Token

endorctl is the single command-line interface for the Endor Labs Agentic Application Security Platform. Local scans, CI scans, dependency listing, container scans, and the MCP server for AI agents all run through it. Install it, then activate a token so your scans are linked to your organization.

# Install endorctl (macOS and Linux) curl -fsSL https://endorlabs.com/install.sh | bash # Windows and per-OS installers: see the install guide at docs.endorlabs.com

Next, generate a token: in the Endor Labs dashboard at app.endorlabs.com, open Settings → API tokens and generate a new token. The value is shown once, so copy it now.

# Link endorctl to your organization endorctl activate-token --token "eyJhbGciOiJSUzI1NiIs...truncated...9k2Q"
$ endorctl activate-token --token "eyJhbGciOiJSUzI1NiIs...truncated...9k2Q" Token activated successfully. Organization: Acme Financial (sandbox) Namespace: acme-financial Signed in as: learner@endorlabs.com endorctl v4.12.0 — latest syntax at https://docs.endorlabs.com
Tip The activated token is stored in your local Endor Labs config, never in the repository. For CI pipelines, prefer keyless OIDC authentication (covered in the GitHub Actions lab) or a dedicated API key with minimal scope.
  • ✓ endorctl installed and available on your PATH
  • ✓ Token activated and your organization name confirmed in the output
2

Connect Your Repository

Scans are organized under projects, and projects are connected to repositories through the SCM integration. In the Endor Labs dashboard, open Settings → Integrations → GitHub and install the Endor Labs GitHub App, granting it access to your organization and to the lab's sample repository, endor-academy/checkout-service.

Then clone the sample repository locally:

# Clone the lab's sample repository gh repo clone endor-academy/checkout-service cd checkout-service
$ gh repo clone endor-academy/checkout-service Cloning into 'checkout-service'... remote: Enumerating objects: 1284, done. Receiving objects: 100% (1284/1284), done. $ cd checkout-service $ ls Dockerfile README.md pom.xml src/
Why the GitHub App matters The app connection is what later enables pull request scan comments, monitoring, and automated upgrade PRs. A token alone is enough to run local scans of any repository on your machine.
  • ✓ Endor Labs GitHub App installed with access to the sample repository
  • ✓ Cloned checkout-service and confirmed pom.xml is present
3

Run Your First Scan

From the repository root, run a full scan. endorctl detects the build system, resolves the dependency tree, builds a call graph from your source, and evaluates which vulnerabilities your code actually reaches.

# Full scan: dependencies, reachability, secrets, and policy evaluation endorctl scan
$ endorctl scan Scanning project: checkout-service Detected: Java (Maven) — pom.xml Resolving dependencies... done (47 direct, 183 total) Building call graph... done (12,438 functions analyzed) Analyzing reachability... done Evaluating policies... done Findings summary Critical: 3 (1 reachable) High: 7 (2 reachable) Medium: 12 (0 reachable) Low: 5 (0 reachable) Secrets: 1 Policy violations: 2 Results uploaded to Endor Labs: https://app.endorlabs.com/acme-financial/projects/checkout-service/findings Scan finished in 2m 41s
Notice The scan found 27 vulnerabilities, but only 3 are reachable through your code. Most scanners would page you for all 27; Endor Labs separates the signal from the noise with function-level reachability so your backlog contains only what your code actually calls.
  • ✓ Ran endorctl scan to completion
  • ✓ Noted how many findings are reachable versus total
  • ✓ Opened the findings view in the dashboard
4

Read Your Findings and Dependency Tree

In the dashboard, the findings list is sorted by severity. Each row shows the package, CVE, CVSS score, and a reachability chip: Reachable, Unreachable, or Unknown. Click the CVE-2021-44228 finding to open its detail view — you will explore it fully in the next step.

From the CLI, endorctl deps prints the resolved dependency tree with the flagged versions inline:

# List the resolved dependency tree endorctl deps
$ endorctl deps com.acme:checkout-service:1.4.2 -- org.apache.logging.log4j:log4j-core:2.14.1 flagged: CVE-2021-44228 (critical 10.0) - REACHABLE -- org.yaml:snakeyaml:1.29 flagged: CVE-2022-1471 (critical 9.0) - unreachable -- org.springframework:spring-webmvc:5.3.16 flagged: CVE-2022-22965 (critical 9.8) - unreachable -- com.fasterxml.jackson.core:jackson-databind:2.13.2 flagged: CVE-2020-36518 (high 7.5) - UNKNOWN -- ... 43 more direct dependencies, 136 transitive
Key terms Reachable: your code has a complete call path to the vulnerable function. Unreachable: the package is in your tree but no path calls the vulnerable function. Unknown: reachability could not be confirmed, usually pending version inference.
  • ✓ Opened the findings list and sorted by severity
  • ✓ Located log4j-core 2.14.1 in the dependency tree
  • ✓ Identified the reachability status of each critical finding
5

Reachability Basics: Read the Call Path

Endor Labs performs function-level reachability analysis across 40+ languages: it maps which vulnerable functions your code actually calls, not just which vulnerable packages are in your tree. Open the CVE-2021-44228 finding and expand the Call path section:

# Call path — CVE-2021-44228 (Log4Shell) Entry point: POST /api/orders (internet-facing) 1. OrderController.createOrder() [your code] 2. OrderService.validatePayment() [your code] 3. Logger.error(paymentCtx) [log4j-api 2.14.1] 4. JndiLookup.lookup() [log4j-core 2.14.1] * vulnerable function

A complete path exists from an HTTP entry point to JndiLookup.lookup(), so the finding is Reachable. This is the classic Log4Shell pattern: attacker-controlled data reaches a log statement that performs a JNDI lookup.

Compare it with CVE-2022-22965 (Spring4Shell) in spring-webmvc: the package is present, but no path from your code reaches the vulnerable data-binding code, so it is Unreachable — context, not a crisis.

Why it matters Zebra used reachability triage to cut SCA noise by 97%. Reachable findings are your backlog; everything else is reference material for auditors and planning.
  • ✓ Traced the call path from the HTTP entry point to JndiLookup.lookup()
  • ✓ Compared the reachable Log4Shell finding with the unreachable Spring4Shell finding
6

Fix Your First Finding and Verify

From the CVE-2021-44228 detail view, Endor Labs offers remediation options: upgrade to the fixed version, apply an Endor Patch backport (for Java and Python, when you cannot take the full upgrade), or open a documented exception. Take the direct upgrade: bump the log4j.version property in pom.xml from 2.14.1 to 2.17.1, rebuild, and re-scan.

# pom.xml: <log4j.version>2.14.1</log4j.version> -> 2.17.1 mvn -q -DskipTests compile # Re-scan to verify the fix endorctl scan
$ endorctl scan Scanning project: checkout-service Detected: Java (Maven) — pom.xml Resolving dependencies... done (47 direct, 183 total) Analyzing reachability... done Findings summary Critical: 2 (0 reachable) [-1 reachable vs. last scan] High: 7 (2 reachable) Medium: 12 (0 reachable) Low: 5 (0 reachable) Policy violations: 0 [-2 vs. last scan] CVE-2021-44228 remediated: log4j-core 2.14.1 -> 2.17.1 Scan finished in 2m 12s
Machine-readable output Every scan can emit results for tooling with endorctl scan --output json or endorctl scan --output sarif — the format CI pipelines and code-scanning tools consume. You will use this in the GitHub Actions lab.
  • ✓ Upgraded log4j-core to 2.17.1
  • ✓ Re-ran the scan and confirmed zero reachable criticals
  • ✓ Confirmed policy violations dropped to zero

🧠 Knowledge Check

Which command links endorctl to your Endor Labs organization?
  • endorctl login --org acme-financial
  • endorctl activate-token
  • endorctl connect --github
  • endorctl auth --login
A finding is marked Reachable when:
  • The vulnerable package is a direct dependency
  • The CVE has a CVSS score of 9.0 or higher
  • Your code has a complete call path to the vulnerable function
  • The package appears anywhere in the dependency tree
Which command prints the resolved dependency tree?
  • endorctl deps
  • endorctl tree
  • endorctl list --dependencies
  • endorctl show deps
In this lab, why was CVE-2021-44228 reachable while CVE-2022-22965 was not?
  • Log4Shell had a higher CVSS score
  • log4j-core was a direct dependency and spring-webmvc was transitive
  • A call path existed from an HTTP entry point to the JNDI lookup function, while no path reached Spring's vulnerable data-binding code
  • The scan policy was configured to ignore Spring findings
