MCP Server & Agent Kit Setup

Challenge
🕓 45 min 🏆 100 XP 🔄 AI Agents 📚 6 steps

🎯 Lab Objectives

  • Start the Endor Labs MCP server and verify its tools
  • Connect an agent in Cursor or Claude Code
  • Ask an agent to triage a finding using reachability data
  • Have the agent fix a finding safely — and prove it with a scan
  • Observe Coding Agent Governance (AURI) inventory and policy
  • Scale with Agent Kit and the Agents Hub
1

Authenticate and Start the MCP Server

Challenge scenario: your team adopted AI coding agents last sprint, and everyone is guessing which ones are safe. Your mission: wire the agents to Endor Labs, let one fix a real finding, and keep every action governed. The MCP server is free for developers.

Prerequisites: endorctl installed and activated (endorctl activate-token — see the first-scan lab). Then start the server:

# Start the Endor Labs MCP server (stdio transport) npx -y endorctl ai-tools mcp-server
$ npx -y endorctl ai-tools mcp-server endorctl authenticated as learner@endorlabs.com (org: acme-financial) Starting Endor Labs MCP server (stdio)... Tools registered: search_findings list and filter findings get_finding_details CVSS, reachability, remediation options get_call_path function-level call path for a finding list_dependencies resolved dependency tree get_package_scores Endor Scores for a package MCP server ready — waiting for a client.
Tip The server speaks stdio, so any MCP-compatible client can drive it. Tool names above are the training set — the current tool list ships with the server (see docs.endorlabs.com).
  • ✓ Authenticated endorctl before starting the server
  • ✓ Started the MCP server and saw the tool registration list
2

Connect Your Agent

Cursor: use the one-click install from the Endor Labs dashboard, or add the server to .cursor/mcp.json:

# .cursor/mcp.json { "mcpServers": { "endor-cli-tools": { "command": "npx", "args": ["-y", "endorctl", "ai-tools", "mcp-server"] } } }

Claude Code: register the server with a single command:

# Register the MCP server in Claude Code claude mcp add endor-cli-tools -- npx -y endorctl ai-tools mcp-server
$ claude mcp add endor-cli-tools -- npx -y endorctl ai-tools mcp-server Added MCP server endor-cli-tools to user config $ claude mcp list endor-cli-tools: npx -y endorctl ai-tools mcp-server (connected)
Also supported The same server works with VS Code (.vscode/mcp.json), Codex, Gemini CLI, IntelliJ, Antigravity, and more — any MCP-compatible client can use these tools.
  • ✓ Connected Cursor (one-click or .cursor/mcp.json) or registered Claude Code
  • ✓ Confirmed the server shows as connected in your agent
3

Ask the Agent to Triage

Open checkout-service in your agent and ask it what matters. The agent answers with reachability data, not raw CVE noise:

# Prompt What is the most exploitable finding in checkout-service? Show me why.
> What is the most exploitable finding in checkout-service? Show me why. [agent] Calling search_findings(sort_by=reachability)... [agent] Calling get_finding_details(CVE-2021-44228)... [agent] Calling get_call_path(CVE-2021-44228)... The most exploitable finding is CVE-2021-44228 (Log4Shell, critical 10.0). log4j-core 2.14.1 is REACHABLE from your code: POST /api/orders -> OrderController.createOrder() -> OrderService.validatePayment() -> Logger.error(paymentCtx) -> JndiLookup.lookup() <- vulnerable function Attacker-controlled order data reaches a log statement that performs the JNDI lookup. Recommended fix: log4j-core 2.17.1, or an Endor Patch backport if you cannot take the upgrade.
What just happened The agent used the MCP tools to pull the same call-path evidence a human triager uses in the dashboard. No pasting of scan exports, no guessing — the triage conversation is grounded in reachability analysis.
  • ✓ Asked the agent for the most exploitable finding
  • ✓ Verified the answer cited a reachable call path, not just severity
4

Ask the Agent to Fix It — and Prove It

Now the loop that makes agents genuinely useful: fix, verify, and ship — all in one pass:

# Prompt Fix CVE-2021-44228 and verify the fix with a scan.
> Fix CVE-2021-44228 and verify the fix with a scan. [agent] Editing pom.xml: log4j.version 2.14.1 -> 2.17.1 [agent] Running: mvn -q -DskipTests compile ... ok [agent] Running: endorctl scan [agent] Critical: 2 (0 reachable) — CVE-2021-44228 resolved [agent] Creating branch fix/log4shell and opening PR... https://github.com/acme-financial/checkout-service/pull/63

The agent edited the dependency, compiled, ran endorctl to prove the finding was gone, and opened a PR with the evidence. To make this behavior consistent, put your remediation policy where agents read it — AGENTS.md or CLAUDE.md in the repository root:

# AGENTS.md (excerpt) - Prefer Endor Patch backports over major dependency upgrades - Change at most one dependency per PR - Always run `endorctl scan` after a fix and include the summary in the PR body
Safe pattern Fix + verify in one loop is the safe pattern: the agent proves the fix with a scan before any human reviews it. A PR that arrives with "verified: 0 reachable criticals" in the description changes the review conversation entirely.
  • ✓ Had the agent apply the fix and run a verification scan
  • ✓ Added remediation guidance to AGENTS.md or CLAUDE.md
  • ✓ Reviewed the PR the agent opened with scan evidence
5

Observe Governance: AURI

Agents with credentials need oversight. In the dashboard, open Coding Agent Governance (AURI): it inventories every agent, model, MCP server, and skill in use across your organization — including the session you just ran. Find your agent session and inspect what it did.

Now watch policy in action. In the PR, ask the agent to publish the fixed artifact to the internal registry. Publishing is sensitive, so the governance policy for publish artifacts is set to ask-a-human:

> Publish the fixed artifact to the internal registry. [agent] I can publish the artifact: mvn deploy -DskipTests [governance] Action requires human approval [governance] Policy: publish-artifacts = ask-a-human [governance] Waiting for approval from #appsec ... [governance] Approved by learner@endorlabs.com (12:41 UTC) [governance] Action logged to the audit trail with agent, model, and MCP server attribution.

Three outcomes are possible for every action type: allow (proceed silently), block (refuse, with the policy name), and ask-a-human (pause for approval). Had the policy been block, the agent would have been refused outright — and the attempt would still be in the audit trail.

Govern like humans Treat agent actions the way you treat human actions: inventory them (AURI), constrain them (allow/block/ask-a-human), and evidence them (audit trail). The context agents read from AGENTS.md/CLAUDE.md makes governance tractable.
  • ✓ Found your agent session in the AURI inventory
  • ✓ Triggered an ask-a-human prompt and approved it
  • ✓ Located the audit entry recording who approved what
6

Scale with Agent Kit and the Agents Hub

You wired one agent. Your team runs several. Two pieces scale this safely:

  • Agent Kit — prewired agent setups for Claude Code, Cursor, Codex, Gemini CLI, and Antigravity that already know the Endor Labs triage-and-fix loop. Install the kit for your editor from the Endor Labs dashboard.
  • Agents Hub — browse agents across the organization, manage delegated credentials, and review agent activity with trust and attribution.

Once the kit is installed, the loop you ran manually becomes routine:

> Work the reachable backlog in checkout-service and propose fixes. [agent] 6 reachable findings. Proposing fixes for the 2 criticals: - CVE-2021-44228 (log4j-core 2.14.1): upgrade to 2.17.1 PR #64 opened — endorctl scan: 0 reachable criticals - CVE-2022-1471 (snakeyaml 1.29): Endor Patch backport proposed PR #65 opened — pending governance approval for the patch build All actions recorded in Agents Hub with trust and attribution.
Challenge wrap-up You connected agents to real security data, let one fix a reachable critical with proof, governed a sensitive action through ask-a-human, and set up the org-wide visibility to do this at team scale — free for developers.
  • ✓ Installed Agent Kit for one editor
  • ✓ Browsed the Agents Hub and located your agent's activity
  • ✓ Confirmed delegated credentials are managed per agent

🧠 Knowledge Check

Which command starts the Endor Labs MCP server?
  • npx -y endorctl mcp start
  • npx -y endorctl ai-tools mcp-server
  • endorctl mcp-server --start
  • npx -y @endor/labs-mcp run
Which command registers the server in Claude Code?
  • claude install endor-cli-tools
  • claude mcp add endor-cli-tools -- npx -y endorctl ai-tools mcp-server
  • claude mcp connect endor-cli-tools
  • endorctl register claude
What does AURI inventory for governance?
  • Only the MCP servers in use
  • Only the models your agents run
  • Agents, models, MCP servers, and skills in use across the organization
  • Repository commits and pull requests
A governance policy set to ask-a-human means the agent:
  • Performs the action and files a report afterward
  • Is permanently blocked from that action
  • Pauses and requests human approval first, and the decision lands in the audit trail
  • Asks the model to double-check itself, then proceeds
