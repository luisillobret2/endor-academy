The Open-Source Dependency Landscape

Modern applications are assembled from open-source components. When a developer adds one package from npm, PyPI, Maven, or NuGet, the resolver typically pulls in dozens of transitive dependencies — libraries the team never chose and rarely reviews, but which ship inside the product and run with the same privileges as first-party code.

💡 Direct vs. Transitive Dependencies

A direct dependency is a package your code explicitly imports. A transitive dependency is a package required by one of your direct dependencies. Log4Shell (CVE-2021-44228) was a transitive dependency for most affected organizations: they never imported Log4j directly, yet it was bundled deep in their dependency trees and internet-facing.

Visibility is the prerequisite for every control that follows. Endor Labs SCA resolves the full dependency graph from manifest and lockfiles, supports monorepos and Bazel builds alongside binary artifact scans, and applies function-level reachability across 40+ languages. It also scores each package with Endor Scores covering activity, popularity, security, and code quality — context that helps teams judge whether a dependency is safe to depend on in the first place.

How Supply Chain Attacks Actually Work

Attackers target the supply chain because a single compromised package can reach thousands of downstream organizations at once. The most common vectors, and the Endor Labs control that addresses each one:

Attack Vector How It Works Endor Labs Control
Typosquatting Publishing a malicious package whose name is one character off a popular library (for example lodas for lodash) Package Firewall blocks known-malicious packages at install time
Dependency Confusion Registering a public package under an internal package name so the resolver prefers the public, malicious version Package Firewall plus policy controls over package sources
Compromised Packages Taking over a maintainer account or a trusted project and publishing a malicious release of a legitimate package Malicious package detection with reachability-based triage
Stolen Secrets Scraping committed credentials and tokens to pivot into cloud accounts and CI/CD systems Secrets detection caught before the commit, one policy from laptop to pipeline
Unpatched Dependencies Exploiting known CVEs in dependencies that were never upgraded because the update queue was too noisy SCA with reachability, upgrade impact analysis, and automated pull requests

These are not theoretical. The 2018 event-stream incident showed a popular package handed to a new maintainer that added a malicious dependency; the 2021 Codecov breach modified a CI uploader script to exfiltrate environment variables; the ua-parser-js hijack published malicious versions after an account takeover; SolarWinds compromised a build pipeline; and XZ Utils in 2024 showed a patient, multi-year effort to plant a backdoor in a compression library. Log4Shell remains the clearest lesson that reachability, not raw CVE counts, should drive urgency.

Controls That Stop Attacks Before They Land

Supply chain defense is a sequence, and each step removes a class of risk before it reaches a developer or a build:

  1. Inventory — A single integration discovers dependencies, vulnerabilities, secrets, and AI models across the codebase, so the organization finally knows what it actually ships.
  2. Block at install time — Package Firewall stops known-malicious packages before they reach developer machines or CI, covering typosquatting, dependency confusion, and compromised packages.
  3. Prevent secret leakage — Secrets detection flags credentials before they are committed, using built-in rules plus custom patterns and one policy that applies from the laptop through the pipeline.
  4. Triage by reachability — Function-level reachability keeps CVEs in code the application never calls out of the backlog, so the remaining findings are the ones worth a sprint.
  5. Remediate automatically — Upgrade impact analysis predicts breakage, Endor Patches backport fixes for Java and Python, and automated pull requests put the fix in the developer’s workflow.

💡 Why Package Firewall Changes the Conversation

Most tools tell you after the fact that a malicious package was downloaded. Package Firewall enforces policy at install time, so a typosquatted or hijacked package never reaches a developer machine or a CI runner. For partners, this is the fastest, most visceral demonstration in the platform — a block that happens in front of the customer.

SBOM and VEX: Evidence Across the Chain

An SBOM (Software Bill of Materials) is a complete inventory of the components in a software product, with versions, licenses, and identifiers. Endor Labs exports SBOMs in CycloneDX and SPDX, supports SBOM import, and pairs exports with VEX (Vulnerability Exploitability eXchange) so a downstream consumer can see whether a listed CVE is actually exploitable in the product rather than merely present.

  • Traceability — when the next Log4Shell lands, the customer can answer “which products contain it?” in minutes instead of weeks
  • Regulatory readiness — SBOMs are the deliverable behind the EU Cyber Resilience Act and US Executive Order 14028 (covered in depth in the Compliance module)
  • Evidence in the pipeline — policies can require an SBOM and enforce findings policies on OSS, license, container, secrets, and GitHub Action findings before a release is approved
