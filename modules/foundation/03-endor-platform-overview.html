Who Is Endor Labs?

Endor Labs is an application security company founded in 2022 in Palo Alto by Varun Badhwar (CEO) and Dimitri Stiliadis (CTO), both previously at Palo Alto Networks, where they built and led Prisma Cloud. The company raised a $25M seed round, a $70M Series A, and a $93M Series B — roughly $188M in total — to build a single platform for software supply chain and application security.

Endor Labs positions itself as an Agentic Application Security Platform, with the tagline “Code without compromise.” One platform covers SCA, SAST, secrets detection, malicious package detection, Package Firewall, coding agent governance, and container scanning — rather than selling each as a separate product with its own integration and policy model.

Customers include Zebra Technologies, Egnyte, Rubrik, Atlassian, Glean, Astronomer, Peloton, Netskope, Five9, Snowflake, OpenAI, and Cursor. Three proof points worth remembering: Zebra Technologies cut noise by 97%, Egnyte reduced mean time to remediate by 70% on its path to FedRAMP, and Rubrik adopted Endor Labs for a Bazel-based build environment where other scanners struggled.

Scan, Triage, Remediate: The Platform Workflow

Every Endor Labs conversation should be anchored on the same three-step workflow. It is the simplest way to explain the platform to both a security leader and a developer:

  1. Scan — discover dependencies, vulnerabilities, secrets, and AI models across the codebase with a single integration. No per-language configuration, no separate agent per scanner, and coverage of monorepos, Bazel builds, and binary artifacts.
  2. Triage — apply reachability analysis and risk scoring so teams focus only on what impacts the application. Function-level call graph analysis keeps vulnerabilities in code that is never called out of the backlog.
  3. Remediate — fix, not just find. Upgrade impact analysis shows what an upgrade will break, AI-powered remediation proposes the change, Endor Patches backports fixes, and automated pull requests land in the developer’s workflow.

Customer adoption follows a predictable arc, and partners can use it as an implementation roadmap:

  • Day 0 — Onboard: connect repositories, run the first scan, establish a baseline of dependencies, vulnerabilities, secrets, and AI models.
  • Day 1 — Prioritize: drive remediation of reachable vulnerabilities first and configure policies so routine triage decisions are automated rather than debated.
  • Day 2+ — Optimize: embed the platform in CI/CD, push findings into developer workflows, and keep a continuous baseline as code and dependencies change.

What the Platform Covers

Six capabilities form the core of the platform. Each one addresses a distinct risk surface, but they share one inventory, one policy engine, and one workflow:

🛡

SCA with Reachability

Function-level reachability across 40+ languages builds call graphs so only vulnerabilities the code actually calls reach the backlog. Includes pre-computed reachability, Endor Scores for package activity, popularity, security, and code quality, Bazel and monorepo support, and binary artifact scans.

🔍

AI SAST

Rule-based SAST with custom rules, cloned rules, exception policies, and AI context rules, plus AI SAST agent-based dataflow analysis that runs across repositories and pull requests, catches logic flaws rule-based scanners miss, and cuts up to 95% of false positives.

🔑

Secrets Detection

Secrets are caught before the commit, with one policy that applies from the developer laptop through the pipeline, supported by built-in rules and custom patterns.

📦

Container Scanning

Reachability from code to image keeps CVEs in packages the application never loads out of the queue. Adds incremental scanning, registry scanning, base image remediation, and artifact signing — with nothing to install in the cluster.

🚫

Package Firewall

Blocks known-malicious packages at install time, before they reach developer machines or CI. Covers typosquatting, dependency confusion, and compromised packages.

🤖

Coding Agent Governance (AURI)

Inventories every coding agent, model, MCP server, and skill, learns architecture from context files such as AGENTS.md and CLAUDE.md, and enforces allow, block, or ask-a-human policies on risky agent actions in real time with a full audit trail.

Beyond those six, the platform includes Endor Patches (backported security fixes delivered through Patch Factory, with JFrog Artifactory and Sonatype Nexus integration), AI Model Discovery (models in code, policies, scores, and Hugging Face organization integration), RSPM for repository misconfigurations such as GitHub settings, SBOM and VEX export and import in CycloneDX and SPDX, PR scans with block-on-findings and PR comments, and a full policy framework spanning finding, exception, action, and remediation policies. Administration is enterprise-ready out of the box: RBAC, SSO via SAML or OIDC with Okta or Entra ID, API keys, namespaces, and notifications, plus integrations with Jira, Slack, Vanta, Wiz, S3, and GitHub Advanced Security.

⚠️ Important for Partners

Be precise about maturity. Endor Labs SAST launched in August 2025 and is AI-native rather than decades-old rule-based scanning — AI SAST reports 2.6x more true positives than frontier AI models on the same code. Endor Patches currently cover Java and Python only. Credibility with a technical buyer depends on stating these boundaries clearly instead of over-claiming.

Deployment, Tooling, and Who It Is For

The platform deploys where the customer needs it and integrates with the toolchain they already run:

  • Deployment: SaaS, or Endor Outpost for environments that require a customer-controlled component inside their infrastructure
  • CLI and automation: the endorctl CLI for scans, policy, and CI jobs, plus a REST API for custom workflows
  • AI-assisted development: an MCP server (npx -y endorctl ai-tools mcp-server) that brings findings and reachability context into Cursor, Claude Code, Codex, VS Code, Gemini CLI, Antigravity, and IntelliJ
  • CI/CD: GitHub Actions, Jenkins, GitLab, Azure DevOps, Bitbucket, CircleCI, Google Cloud Build, and Buildkite, with keyless OIDC authentication for GitHub, AWS, Azure, and GCP

Three buyer profiles show up again and again in partner-led deals:

  • Security teams drowning in noise — they already own SCA and cannot close the backlog. Reachability turns an unmanageable queue into a prioritized list, and policies automate the triage decisions they repeat every week.
  • Engineering-heavy organizations — monorepos, Bazel builds, and dozens of languages break scanners designed for a single ecosystem. This is the profile where deep language coverage and binary artifact scans decide the deal.
  • AI-adopting teams — teams rolling out coding agents need governance over what those agents install, change, and access, plus an inventory of the models and MCP servers already in use.
