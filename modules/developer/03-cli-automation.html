One Binary for Every Surface

endorctl is the single command-line tool that drives the Endor Labs platform from a laptop, a container, or a CI runner. One binary covers every surface developers and automation need:

  • Scans — endorctl scan runs SCA with reachability, plus SAST, secrets, and container analysis according to the scan profile
  • Dependency inventory — every scan resolves the complete direct and transitive dependency tree, which you can explore from the CLI or the console
  • PR scans — scan pull requests so findings land as PR comments, and can block merges when policy requires it
  • Container scans — analyze images, with reachability from your code into the image
  • Any pipeline — because it is a plain binary with documented exit codes, endorctl gates builds in whatever CI system the team already owns

💡 Same CLI, Laptop to Pipeline

Behavior is identical whether you run endorctl locally or in CI: the same commands, the same scan profile, the same policy. When a gate fails in the pipeline, you can reproduce exactly what CI saw on your own machine — no “works on my laptop” drift.

Install, Authenticate, and Scan

Install the binary with the packaged installer for your OS (or pull the container image on a CI runner), then run the three commands that do 90% of the work:

# Verify the installation
endorctl --version

# Authenticate with an API token created in the console
endorctl activate-token --token=$ENDOR_TOKEN

# Scan the current repository
endorctl scan

Results land in your project in the console at app.endorlabs.com: the dependency tree, prioritized findings, and secrets. From there, two variations matter for automation:

  • PR scans — run endorctl from CI against pull requests; findings appear as PR comments and policy violations can block the merge
  • Keyless authentication in CI — on GitHub, AWS, Azure, and GCP, prefer keyless OIDC authentication over stored tokens: nothing secret sits in a pipeline, so nothing can leak

Exact flags evolve between releases — confirm current options with endorctl scan --help before you script them into a runbook.

Scan Profiles: Repeatable by Construction

A scan profile defines what a scan does: which languages and toolchains to analyze, which checks run (SCA, SAST, secrets, containers), and how results are reported. There are three ways to configure one:

  1. Auto-detection — endorctl detects the toolchains in your repository across 40+ languages and builds a profile on the first scan
  2. scanprofile.yaml — pin the profile in a file checked into the repository, so scans are declarative, reviewable in a PR, and identical for every teammate and pipeline
  3. UI or API — manage profiles centrally for consistency across an entire organization

💡 Profiles Are the Contract Between Developers and Security

Because the same profile drives local and pipeline scans, “what will CI say?” has a deterministic answer — run the scan locally with the pinned profile. Teams that treat scanprofile.yaml as code get security behavior that changes only when someone reviews a diff.

Exit Codes, CI Gating, and Scripting Patterns

endorctl documents its exit codes, which is what makes CI gating trivial: a scan exits 0 when the code passes policy and non-zero when it does not. Any pipeline that can run a shell can gate on Endor Labs findings:

# Gate a build on the scan result
endorctl scan
status=$?

if [ $status -ne 0 ]; then
    echo "Security gate failed (exit code $status) - see scan output"
    exit $status
fi

The same pattern works everywhere Endor Labs ships CI/CD support: GitHub Actions, Jenkins, GitLab, Azure DevOps, Bitbucket, CircleCI, Google Cloud Build, and Buildkite.

Environment Authentication Typical gate
Developer laptop API token via endorctl activate-token Run the pinned profile before opening a PR
GitHub Actions Keyless OIDC (no stored secrets) Fail the job on non-zero exit; post PR comments
Self-hosted runners Scoped service token in the secret manager Exit-code gate identical to cloud runners
Any other CI API token or OIDC where available endorctl scan + $? is the whole integration

⚠️ Important for Partners

Exit-code gating is the fastest enterprise win in the CLI story: one command in a pipeline turns findings into an enforceable policy. In demos, flip a policy in the console and show the pipeline go green to red on the very next run — that moment lands the “security without workflow change” promise better than any slide.
